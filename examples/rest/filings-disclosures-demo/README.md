## Background

Public companies file regular disclosures with the SEC: annual reports (10-K), quarterly reports (10-Q), current event reports (8-K), insider transactions (Form 4), and more. These filings are the primary source of truth for a company's financial condition, risk profile, and material events.

The raw filings live on [SEC EDGAR](https://www.sec.gov/edgar/searchedgar/companysearch), but extracting structured data from them is difficult. EDGAR serves HTML and SGML documents with inconsistent formatting across filers and time periods. Parsing section boundaries, identifying risk factors, or comparing disclosures across companies requires significant preprocessing.

Massive's filings and disclosures API endpoints (currently in beta) provide clean, structured access to this data through a standard REST interface. Instead of scraping EDGAR and writing custom parsers, you can query for a company's risk factors, read specific 10-K sections as plain text, or search the full EDGAR index by form type and date.

## Why this matters

**Structured risk analysis.** The risk factors endpoint classifies each disclosed risk using a consistent taxonomy. This means you can compare risk profiles across companies or track how a single company's risk disclosures change between filings. The taxonomy endpoint exposes the full classification hierarchy so you can see every category the system uses.

**Full-text access to key sections.** The 10-K sections endpoint returns the plain text of specific sections (currently Risk Factors and Business). No HTML parsing, no dealing with exhibit attachments or formatting inconsistencies. The 8-K endpoint does the same for current event reports, returning only the Items section content.

**Filing metadata search.** The EDGAR index endpoint provides a searchable index across all SEC form types. Filter by ticker, form type, and filing date to find specific disclosures, then use the `filing_url` to link back to the original SEC document.

## What's inside

This repo contains a single `main.py` with seven subcommands. Five are thin wrappers around individual API endpoints. Two (`compare` and `timeline`) combine data from the risk factors endpoint to answer analytical questions.

| Subcommand | Aliases | What it shows |
|------------|---------|---------------|
| `index` | | Filing metadata: form types, dates, issuers, and SEC document links |
| `10k` | | Plain-text content from Risk Factors or Business sections of annual reports |
| `8k` | | Parsed Items section text from current event reports |
| `risks` | | Classified risk disclosures with primary/secondary/tertiary categories and supporting quotes |
| `taxonomy` | `tax` | The full classification hierarchy used to categorize risk factors |
| `compare` | `cmp` | Side-by-side risk factor profiles across two or more companies |
| `timeline` | `tl` | How a company's risk factor disclosures changed between filing periods |

All five underlying endpoints are currently in beta. Response schemas and availability may change.

- Python 3.10+

- Massive API key

## Quickstart

1. **Clone the repository:**
   ```bash
   git clone https://github.com/massive-com/community.git
   cd community/examples/rest/filings-disclosures-demo
   ```

2. **Install dependencies:**
   ```bash
   uv sync
   ```

3. **Set up credentials:**
   ```bash
   cp .env.example .env
   # Edit .env and add your API key
   ```

   Your `.env` file should contain:
   ```
   MASSIVE_API_KEY=your-api-key
   ```

4. **Get your key:**
   - Sign up at [massive.com](https://massive.com/) and copy your API key from the dashboard.

## Usage

### EDGAR index

Search the master filing index by ticker, form type, and date. Returns metadata for every matching filing, including the direct SEC EDGAR link.

```bash
uv run python main.py index AAPL                           # Recent filings, all types
uv run python main.py index AAPL --form-type 10-K          # Only 10-K annual reports
uv run python main.py index TSLA --form-type 8-K --limit 5 # Last 5 Tesla 8-K filings
uv run python main.py index MSFT --save                    # Save results to JSON
```

uv run python main.py 10k MSFT --date 2024-01-01           # Filed on or before date

## How it works

### Massive Python client

This demo uses the `massive` Python client (v2.3.2+). The `risks`, `taxonomy`, `compare`, and `timeline` subcommands use dedicated SDK methods (`list_stocks_filings_risk_factors` and `list_stocks_taxonomies_risk_factors`), which return typed model objects with auto-pagination. The `index`, `10k`, and `8k` subcommands use the client's internal `_get` method to call beta endpoints that don't have dedicated SDK wrappers yet. All subcommands authenticate through the same `RESTClient` instance.

### Text previews

The 10-K and 8-K endpoints can return large text payloads (a full Risk Factors section can be 40,000+ characters). The demo truncates these to readable previews in the terminal and shows the full character count. Pass `--save` to export the complete text to a JSON file in the `data/` directory.

### Structured risk classification

The risk factors endpoint returns pre-classified risk disclosures. Each entry includes:

- `primary_category`, `secondary_category`, `tertiary_category`: a three-level classification from a standardized taxonomy
- `supporting_text`: the passage from the filing that supports the classification

This structure means you can filter, group, and compare risks programmatically without parsing the raw filing text yourself. The taxonomy endpoint shows the full set of categories the system uses.

### Cross-company and cross-filing analysis

The `compare` and `timeline` subcommands demonstrate what you can do with structured risk data that would be impractical with raw EDGAR filings. `compare` fetches each ticker's most recent risk factors, pivots them by primary category, and identifies shared and unique secondary categories across companies. `timeline` fetches multiple filing periods for a single ticker and diffs the secondary categories between consecutive filings to show what was added or removed. Both operate at the secondary category level, which is specific enough to be useful without being too noisy.

### Sorting and pagination

All endpoints support `sort` parameters (e.g. `filing_date.desc`) and return a `next_url` field for pagination. The demo defaults to `filing_date.desc` to show the most recent results first. For larger result sets, the `--limit` flag controls how many results to fetch per request.

## Endpoints reference

| Endpoint | Path | Max limit | Notes |
|----------|------|-----------|-------|
| EDGAR Index | `/stocks/filings/v1/index` | 50,000 | Covers all SEC form types |
| 10-K Sections | `/stocks/filings/10-K/v1/sections` | 9,999 | Risk Factors and Business sections |
| 8-K Text | `/stocks/filings/8-K/v1/text` | 999 | Items section only, excludes frontmatter |
| Risk Factors | `/stocks/filings/v1/risk-factors` | 49,999 | Classified with three-level taxonomy |
| Risk Taxonomy | `/stocks/taxonomies/v1/risk-factors` | 999 | Full category hierarchy with descriptions |

All endpoints accept `ticker`, `cik`, and `filing_date` filters (with comparison operators like `.gte`, `.lte`, `.any_of`). See the [API documentation](https://massive.com/docs/rest/stocks/filings/) for full parameter details.

## Troubleshooting

- **"Access denied" or 403 errors**
  - Verify `MASSIVE_API_KEY` is set correctly in `.env`.
  - These endpoints are in beta and may require a specific plan tier.

- **"Endpoint not found" or 404 errors**
  - The filings endpoints are in beta. Confirm your account has access.
  - Check that the endpoint path matches the current API version.

- **No results returned**
  - The `index` endpoint has broad coverage (it mirrors EDGAR metadata), but the `8k` and `10k` endpoints require parsed filing content, which is not yet available for all companies during beta. If a filing appears in `index` but not in `8k` or `10k`, parsed text for that filer has not been processed yet.
  - Check your date filters. Use `--date` with a recent date, or omit it to get the latest filings.

- **Truncated text in terminal**
  - This is by design. The demo shows a preview of long text fields. Use `--save` to export the full content to JSON.
